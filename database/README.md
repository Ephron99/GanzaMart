# Ganza Mart — Database

MySQL **8.0** scripts for `GanzaMart_db`. Verified executing against MySQL 8.0.46 on
this machine (service `MySQL80`, **port 3306** — *not* the 3006 mentioned in the spec;
check your own server with `SHOW VARIABLES LIKE 'port';`).

## Files

| File | Contents |
|---|---|
| `schema.sql` | Drops & recreates `GanzaMart_db`, creates all 19 InnoDB tables with FKs, unique constraints, indexes, FULLTEXT search, CHECK constraints and timestamps |
| `seed.sql` | Admin + 3 demo customers (bcrypt hashes), 12 categories, 20 products, gallery images, 3 coupons, 3 test orders with items/payments/shipments/status history, reviews, wishlists, newsletter & contact samples |

## How to run — MySQL Workbench (recommended)

1. Open Workbench → connect to your **local MySQL Server** instance
   (hostname `localhost`, port **3306**, user `root`).
2. **File → Open SQL Script…** → `database/schema.sql` → click ⚡ (Execute).
3. Then open `database/seed.sql` → Execute.
4. Refresh *Schemas* — you should see `GanzaMart_db` with 19 tables.

## How to run — command line (PowerShell)

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -P 3306 --default-character-set=utf8mb4 -e "source c:/Users/Admin/Documents/GanzaMart/database/schema.sql"
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -P 3306 --default-character-set=utf8mb4 -e "source c:/Users/Admin/Documents/GanzaMart/database/seed.sql"
```

(linux/macOS: `mysql -u root -p -P 3306 < schema.sql`)

Re-running is safe: `schema.sql` drops and recreates the database from scratch
(⚠️ this erases all data — take a Workbench backup first if needed).

## Demo accounts (seeded — passwords are bcrypt-12 hashes, never plaintext)

| E-mail | Password | Role |
|---|---|---|
| admin@ganza.com | Admin@123 | administrator |
| alice@example.com | Alice@123 | customer (has delivered order) |
| bo@example.com | BoBo@123 | customer (order in processing) |
| carla@example.com | Carla@123 | customer (has delivered order + wishlist) |

`users.token_version` starts at 0. Logging out (or changing a password) increments it,
which invalidates every JWT signed before that moment — MySQL-side revocation for a
stateless token.

Hashes were generated by `server/tools/hash-seed-passwords.mjs`
(`node tools/hash-seed-passwords.mjs`) — rerun it to regenerate for new passwords.

## Quick sanity checks after seeding

```sql
SELECT COUNT(*) FROM products;   -- 20
SELECT COUNT(*) FROM categories; -- 12
-- Order totals must equal line totals, and total = subtotal - discount + shipping:
SELECT o.id, o.subtotal, SUM(oi.line_total) AS items_sum
FROM orders o JOIN order_items oi ON oi.order_id = o.id GROUP BY o.id;
```

## Known MySQL 8 limitations handled here

- Generated columns **cannot contain subqueries** → product ratings are computed by
  `LEFT JOIN AVG(reviews.rating)` in the API, and `coupon_redemptions.user_id` is
  written by the service layer at checkout.
- Generated columns **cannot reference AUTO_INCREMENT** → `orders.order_number` is a
  plain UNIQUE column filled by the order service right after INSERT.
